# 请求过滤

拒绝文本中含有指定关键词或命中指定正则表达式的请求，也可以中止命中规则的模型回复。

## 添加方法

1. 在控制台打开“请求处理”，点击“添加”。
2. 选择“请求过滤”，在“设置”里添加规则或关键词列表。
3. 在“用在哪里”选择“所有请求”、“指定分组”或“只在渠道添加”。选“只在渠道添加”时，还要在渠道设置的“请求处理插件”里加上这个实例。“模型”可以限定只对部分模型生效。
4. 保存。编辑时可以用“试一试”按当前设置在示例请求上运行插件；“请求处理”页面的“试运行”会运行已保存的实例。

## 设置

- **规则**：命中任一规则的请求会被拒绝，最多 500 条。每条规则包括：
  - **关键词或表达式**：要查找的文本。
  - **匹配方式**：“关键词”（默认）在文本任意位置查找；“正则表达式”使用 JavaScript 语法，无法编译的表达式在保存时就会被拒绝。
  - **区分大小写**：默认关闭。
  - **规则 ID**：命中时记录在日志里。留空时按顺序编号为 `rule-1`、`rule-2` 等。
- **关键词列表**：每行一个关键词，请求中出现任意一个就拒绝。适合很长的词表。
- **关键词区分大小写**：默认关闭。
- **拒绝提示**：客户端看到的提示。留空时使用网关的默认提示。
- **检查回复**：默认关闭。开启后，命中规则或关键词列表的模型回复会被中止。

## 检查范围

- Chat Completions、Responses、Claude Messages 和 Gemini 请求中的全部文本：系统提示词、所有消息、工具调用及其结果，以及工具声明。
- 文本补全和图片生成请求的 prompt、Embedding 请求的输入，以及 Rerank 请求的查询和文档。
- 视频、音乐生成等任务提交和 Midjourney 提交的提示词、反向提示词和歌词。
- 请求里直接附带的文本、PDF 和 DOCX 文件。
- 发往上游的最终请求体会再检查一次，因此渠道参数覆盖添加的文本也会被检查。

## 对客户端的影响

- 命中的请求会被拒绝，返回 HTTP 400 和错误码 `request_rejected`。提示内容是你设置的拒绝提示，未设置时为默认提示“请求被策略拒绝”，后面附上 `(code: request_filtered)`。请求不会再发往其他渠道。
- 开启“检查回复”后，命中的回复会被中止：非流式回复变为 HTTP 400 和错误码 `response_rejected`，流式回复以错误事件结束。
- 日志不会记录命中的文本。管理员能看到命中的规则 ID，关键词列表命中时显示为 `keywords`。
- 插件处理某个请求出错时，请求失败，返回 HTTP 500 和错误码 `request_plugin_failed`。

## 限制

- 不检查图片，也不检查请求只通过 URL 或文件 ID 引用的文件。
- 流式回复会稍作缓冲，以便找到跨数据块的匹配。有正则表达式规则时会缓冲 256 个字符。
- 回复检查只覆盖 Chat Completions、Responses、Claude Messages 和 Gemini 回复里的文本，不检查任务结果、图片和音频。
- 需要 new-api v1.0.0-rc.50 或更高版本。
