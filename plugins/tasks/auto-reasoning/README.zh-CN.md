# 自动推理强度

根据每个请求的规模设置推理强度。你可以写“带工具的请求多想一想”这样的规则，网关按第一条命中的规则设置推理强度，并把它转换成各模型接口对应的字段，效果和 `@effort` 模型修饰符相同。

## 添加方法

1. 在控制台打开“请求处理”，点击“添加”。
2. 选择“自动推理强度”，填写“设置”。
3. 在“用在哪里”选择“所有请求”、“指定分组”或“只在渠道添加”。选“只在渠道添加”时，还要在渠道设置的“请求处理插件”里加上这个实例。
4. “模型”选择“指定模型”，只选支持推理的模型。其他模型收到带推理强度的请求时可能会拒绝。
5. 保存。编辑时可以用“试一试”按当前设置在示例请求上运行插件；“请求处理”页面的“试运行”会运行已保存的实例。

## 设置

- **规则**：从上往下检查，第一条所有条件都满足的规则决定推理强度。没有条件的规则对所有请求都命中。最多 50 条。
- 每条规则选择一个“推理强度”，并可以设置以下条件：
  - **最少消息数**：请求的消息数不少于此值。
  - **最少工具数**：请求的工具数不少于此值。
  - **最后一条用户消息长度**：最后一条用户消息的字数不少于此值。
  - **文本总长度**：请求里全部文本的字数不少于此值。
  - **仅限含图片**：开启后，只有含图片的请求才命中。
- 默认规则：带至少一个工具的请求，以及文本不少于 4000 字的请求，使用“高”强度。
- **默认推理强度**：没有规则命中时使用的强度。默认“不设置”，这类请求保持原有强度。
- **最低推理强度**和**最高推理强度**：把插件设置的强度限定在这两个界限之间。两项默认都是“不设置”。
- **覆盖请求中的推理强度**：默认关闭，请求体或 `@effort` 模型修饰符已经设置了强度的请求会保留原值。开启后总是使用插件给出的强度。

推理强度从弱到强依次为“关闭”（不思考）、“极低”、“低”、“中”、“高”、“极高”和“最高”。

## 对客户端的影响

- 插件不会拒绝请求，只会添加或修改推理强度。
- 插件设置的强度会显示在该请求的使用日志里。
- 插件处理某个请求出错时，请求按原有强度继续发送。

## 限制

- 适用于 Chat Completions、Responses、Claude Messages 和 Gemini 请求。
- 网关或渠道开启请求体透传时，插件不会运行。
- 不支持推理的模型可能拒绝请求，请把插件限定在推理模型上。
- 需要 new-api v1.0.0-rc.50 或更高版本。
