# 内容审核

用 OpenAI 兼容的审核接口（例如 OpenAI 的 `/v1/moderations`）检查用户发送的内容，拒绝被审核接口标记的请求。还可以检查图片、文档和模型回复。

## 添加方法

1. 在控制台打开“请求处理”，点击“添加”。
2. 选择“内容审核”，在“设置”里填写审核接口地址和 API 密钥。
3. 在“用在哪里”选择“所有请求”、“指定分组”或“只在渠道添加”。选“只在渠道添加”时，还要在渠道设置的“请求处理插件”里加上这个实例。“模型”可以限定只对部分模型生效。
4. 保存。编辑时可以用“试一试”按当前设置在示例请求上运行插件；“请求处理”页面的“试运行”会运行已保存的实例。两者都会真实调用审核接口。

## 设置

- **审核接口地址**：接受 OpenAI 审核请求的接口，默认 `https://api.openai.com/v1/moderations`。
- **API 密钥**：以 Bearer 令牌发送。接口不需要密钥时留空。
- **审核模型**：默认 `omni-moderation-latest`。留空时使用接口的默认模型。
- **检查的文本**：“最后一条用户消息”（默认）或“全部用户消息”。
- **检查图片**：默认开启，被检查消息里的图片也会发给审核接口。
- **拦截的类别**：留空时拒绝所有被标记的请求。选择“骚扰”“暴力”等类别后，只拒绝因这些类别被标记的请求。
- **审核回复**：默认关闭。开启后同时审核模型的回复。

## 检查范围

- Chat Completions、Responses、Claude Messages 和 Gemini 请求里的用户消息。系统提示词、助手消息和工具结果不检查。
- 文本补全和图片生成请求的 prompt，以及 Embedding 请求的输入。
- 视频、音乐生成等任务提交和 Midjourney 提交的提示词。反向提示词不检查。
- 被检查消息里附带的图片，或以 `http`、`https` 地址引用的图片，每个请求最多 3 张。请求里直接附带的图片超过 20 MiB 时跳过。
- 被检查消息里附带的文本、PDF 和 DOCX 文件，每个请求最多 4 个，每个只读前 10000 个字符。
- 发往本网关 `/v1/moderations` 的请求从不检查，因此可以把审核接口指向本网关，并填写它的一个令牌。

## 对客户端的影响

- 被标记的请求会被拒绝，返回 HTTP 400、错误码 `request_rejected` 和提示“The request was flagged by content moderation (code: moderation.flagged)”。请求不会发往任何渠道。
- 文本太长、4 次审核调用也检查不完时，请求被拒绝，代码为 `moderation.too_long`。
- 审核接口无法访问或返回错误时，请求失败，返回 HTTP 500 和错误码 `request_plugin_failed`，请求不会发出。
- 开启“审核回复”后，被标记的回复会被中止：非流式回复变为 HTTP 400 和错误码 `response_rejected`，流式回复以错误事件结束。审核接口未能检查回复时，回复同样会中止，错误码为 `request_plugin_failed`。
- 被拦截请求的日志会显示拦截它的类别。

## 限制

- 每次检查最多调用审核接口 4 次，总共最多等待 30 秒。先检查文本，剩余的调用次数再用来检查图片，每次一张。
- 开启“审核回复”后，流式回复大约每 1000 字送达一次，每段都要等审核接口通过才发给客户端。
- 回复审核只覆盖 Chat Completions、Responses、Claude Messages 和 Gemini 回复里的文本，不检查任务结果、图片和音频。
- 需要 new-api v1.0.0-rc.50 或更高版本。
