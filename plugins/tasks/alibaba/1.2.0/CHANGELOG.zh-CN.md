# Changelog

## [1.2.0]

### Added

- 补齐 `wan2.2-kf2v-flash` 和 `wan2.2-s2v` 的支持，包括原生提交路由 `/ali/api/v1/services/aigc/image2video/video-synthesis`，以及数字人结果字段 `output.results.video_url`。
- 在已支持的 Wan 2.1 至 3.0 模型基础上，补充现有 Wan 2.6 地域变体和 Wan 2.7 日期版本的模型声明。

### Changed

- 合并请求参数后，按模型应用分辨率、宽高比、时长和素材规则。原生协议字段优先于兼容字段。
- 兼容请求支持以 `*` 或 `x` 分隔的像素 `size` 及分辨率档位。目标模型支持比例控制时保留对应比例；图生视频模型保持输入素材的比例。
- `wan2.7-t2v` 默认使用 `resolution: 1080P` 和 `ratio: 16:9`，替代旧版 `size: 1280*720` 参数。
- `wan2.7-i2v` 默认分辨率从 `720P` 调整为 `1080P`。
- `wan2.6-t2v` 和 `wan2.6-t2v-us` 默认尺寸从 `size: 1280*720` 调整为 `size: 1920*1080`。
- `wan2.2-s2v` 默认分辨率从 `720P` 调整为 `480P`。时长由音频决定，不再按固定 5 秒估算；按 20 秒预扣，完成后读取实际时长并保留小数秒。
- Wan3 显式像素尺寸保留其对应比例，不再回退为 `adaptive`。
- Wan3 请求包含参考视频或使用智能时长时，按 30 秒预扣。完成用量包含输入和输出视频时长；Wan2.7 视频续写使用完整返回视频的时长。

- 完成用量格式错误或超过上限时交由宿主校验拒绝，不再将超大的时长截断为 3600 秒。

### Fixed

- 修复省略 `size` 时，将 `wan2.7-t2v` 分辨率档位按旧版像素尺寸校验的问题。
- 保留原生 `input` 和 `parameters`，包括显式传入的 `prompt_extend: false`、`watermark: false`、`audio: false` 和 `seed: 0`。
- 修复 metadata 时长与统一请求字段之间的优先级，同时保留 Wan3 智能时长功能。
- 任务结果与产物下载统一使用数字人结果中的视频地址。

### Migration

- **价格配置：** 本次升级不会自动修改管理员价格或迁移计费表达式。已有基于 `u("seconds")` 和 `u("resolution")` 的任务用量表达式仍然兼容，无需仅因本次升级改写语法；但应为本次启用的模型及分辨率档位补齐缺失的价格配置。
- **计费模式：** 如果当前采用按次计费，而希望 `wan2.2-s2v` 或 Wan3 按实际完成时长结算，需要将相应模型改为基于 `u("seconds")` 的任务用量表达式，并配置适用的每秒价格。插件不会自动切换计费模式。
- **Wan3 表达式：** `u("seconds")` 现在包含输入与输出视频时长。若自定义表达式已单独加算输入视频时长，应删除这部分额外计算，避免重复收费。
- **分辨率价格档位：** `wan2.7-t2v`、`wan2.7-i2v`、`wan2.6-t2v` 和 `wan2.6-t2v-us` 的默认输出调整为 1080P；请确认 1080P 档位价格。若需保持原来的 720P 输出，Wan2.7 原生请求应显式设置 `parameters.resolution: "720P"`，Wan2.6 文生视频应设置 `parameters.size: "1280*720"`。`wan2.2-s2v` 默认改为 480P，也需确认对应档位价格。
