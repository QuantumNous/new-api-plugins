# 图片压缩

在网关把请求发往上游之前，压缩请求里的大图片。图片变小后上传更快；有损模式还能把超出模型需要的大图缩小。如果压缩后的图片不比原图小，网关会保留原图。

## 添加方法

1. 在控制台打开“请求处理”，点击“添加”。
2. 选择“图片压缩”，填写“设置”。
3. 在“用在哪里”选择“所有请求”、“指定分组”或“只在渠道添加”。选“只在渠道添加”时，还要在渠道设置的“请求处理插件”里加上这个实例。“模型”可以限定只对部分模型生效。
4. 保存。编辑时可以用“试一试”在带图片的示例请求上运行插件，对比原图和发往上游的图片。

## 设置

- **压缩方式**：“无损”（默认）或“有损”。
  - **无损**保留全部像素，把 PNG 和 GIF 图片转为 WebP，不缩放尺寸。JPEG 和 WebP 图片保持原样。上游需要支持 WebP 图片。
  - **有损**会重新编码 JPEG、PNG、GIF 和 WebP 图片，并缩小过大的图片。
- **最小图片大小**：不小于此大小的图片会被压缩，默认 512 KB。
- **最长边**（仅有损模式）：较长边超过此值的图片会等比缩小到这个尺寸，即使文件小于最小图片大小也一样。默认 2048 像素。
- **输出格式**（仅有损模式）：“自动”（默认）时，有透明部分的图片用 PNG，其余用 JPEG。也可以固定为“JPEG”或“PNG”。
- **JPEG 质量**（仅有损模式）：1 到 100，默认 85。越高越清晰，节省的空间越少。

## 对客户端的影响

- 插件不会拒绝请求，模型收到的是压缩后的图片。
- 使用日志会列出每张被替换的图片，以及替换前后的格式和大小。
- 插件处理某个请求出错时，图片按原样发送。

## 限制

- 只压缩以 base64 数据直接放在请求里的图片。通过 URL 或文件 ID 引用的图片不处理。
- 视频生成等任务提交，以及网关以表单形式发往上游的请求（例如图片编辑），插件不会运行。
- 网关或渠道开启请求体透传时，插件不会运行。
- 动图 GIF、超过 20 MiB 的图片和超过 4000 万像素的图片按原样发送。
- 每个请求最多压缩 32 张图片，其余按原样发送。
- 需要 new-api v1.0.0-rc.50 或更高版本。
